# git commit SIGSEGV(139) 问题报告

> 日期：2026-11-07 ｜ 归属：node-bridge-workspace ／ pi-desktop-android 112-cli-integration 平台边界 G1
> 目标读者：维护者、aosp-git-cli 上游、下一轮 git 构建修复立项
> 现状一句话：`aosp-git-cli` 的 `libgit_cli.so`（git 2.56.0，arm64）在 Android App 真实 SELinux 域下，`git commit`
> 落 ref/对象时 `link(2)` 被拒后**不回退 `rename(2)`、直接解引用空指针**，进程收 `SIGSEGV`（rc=139）；**原生 arm64
> 真机与模拟器翻译层同样复现**（2026-11-07 已裁决），属 git 二进制健壮性缺陷被平台 SELinux 策略触发，**无配置层 workaround**。

---

## 一、具体问题（Problem）

### 1.1 现象定义
在 Android 应用私有数据目录（`app_data_file` 标签）执行 `git commit` 时，进程稳定崩溃，退出码 **139**（SIGSEGV）。
该桌面/常规 Linux 上本可正常完成的本地版本控制操作，在 Android App 沙箱内成为不可用路径。

### 1.2 触发条件
- **SELinux 域**：`u:r:untrusted_app_34:s0`（App 真实生产域）或 `runas_app`（debug run-as 域）——**两域都触发**。
- **落盘路径**：`git commit` 把 loose object / ref 经 **`link(2)`（hardlink）原子落盘**进 `objects/` / `refs/`。
- **平台裁决**：SELinux enforcing 下，`untrusted_app → app_data_file` 的 `link` 被 `neverallow` 级约束拒绝
  （`avc: denied { link }`），而**同目录 `rename(2)` 是允许的**。
- **git 缺陷**：该 2.56.0 arm64 构建在 `link` 报错路径上**未做空指针保护**，不回退 `rename` 即解引用。

### 1.3 证据链条（详见 §四）
`AVC link denied`（audit 1008/1009，名字 `tmp_obj_*`）→ 随即 `Fatal signal 11 (SIGSEGV), fault addr 0x0`，
回溯 #00–#06 全在 `libgit_cli.so`（#07 `__libc_init`），无应用栈 —— NULL 指针解引用，崩溃自 git 自身。
`tmp_obj_*` 为 git 写 loose object 的临时名，证明崩溃点在**对象临时文件 hardlink 进 `objects/` 的落盘环节**。

## 二、现象（Symptoms，设备实测）

### 2.1 逐操作判别（崩溃面界定）
在完整产品 env + git identity 齐备前提下：

| git 操作 | 退出码 | 判定 |
|---|---|---|
| `git init` | 0 | 正常（不触发 link 落盘） |
| `git hash-object -w` | 0 | loose object 直写正常 |
| `git write-tree` | 0 | 正常 |
| `git add` | 0 | 索引写正常 |
| `git commit-tree`（缺 identity） | 128 | 提前因 identity 失败，走不到 link 路径，不崩 |
| **`git commit`**（identity 齐备） | **139** | 走到 ref/对象 link 落盘即崩 |
| `git log`（commit 失败后） | 128 | `branch 'master' does not have any commits yet` |

**结论**：崩溃**严格限定在 `git commit` 的 ref/对象 `link` 落盘路径**；不触发该路径的写操作全部正常。
`ls-remote` / clone / fetch 走 TLS（静态 curl+OpenSSL）不受影响。

### 2.2 复现环境 × 结论
| 环境 | git 版本 | 结果 |
|---|---|---|
| 模拟器 emulator-5554（Android 17 / API37，x86_64 + berberis 翻译） | 2.56.0 | **139 复现**（2026-11-05） |
| **真机 8f155833（小米 Mi 11，Android 11 / API30，原生 arm64 无翻译层）** | 2.56.0 | **139 复现**（2026-11-07，本轮 P4 裁决） |

> **关键裁决（2026-11-07）**：真机**原生 arm64、无 berberis/ndk_translation** 环境下 `git commit` 同样
> `SEGFAULT(139)`（本会话 logcat：`[cli-probe] git 工作流冒烟 FAIL（commit=SEGFAULT(139)，log=fail，272ms，7 步）`）。
> ⇒ **该缺陷非模拟器翻译层叠加，而是 aosp-git-cli arm64 构建在 SELinux 拒 link 后不回退 rename 而 NULL 解引用的
> 真机固有问题**。此前「P4 原生 arm64 裁决」项正式关闭，结论不需要修订。

### 2.3 三通道一致性
TERM 终端面板 / ptyBash（PTY）/ Agent `bash`（android-exec）三通道统一为 login shell `sh -l` 自动 source
`$HOME/.profile` 的 `git()` shell 函数（`exec '<nativeDir>/libgit_cli.so'`），故崩溃在三通道**一致复现**，与运行容器无关。

## 三、后果（Consequences）

1. **本地提交不可用**：App 沙箱内任一工作区执行 `git commit` 即进程段错误。对「在设备上做本地版本管理、提交产物快照」
   的诉求形成硬阻断；任何依赖 `commit` 的工具链（git 工作流、CI 式提交脚本）在真域不可运行。
2. **脏进程/产物流失**：崩溃发生在对象落盘环节，未产生提交（`git log` 报无提交），同时可能残留半写对象/临时文件
   `tmp_obj_*`，需要清理；多次崩溃可能在私有目录累计碎片。
3. **能力面如实降级（宪法 A6）**：产品不得静默伪装 `git commit` 可用。能力清单/`promptGuidelines` 必须明示该边界，
   并把「本地 commit 受限」作为已知平台边界登记，避免 Agent/用户误以为命令失败是代码写错。
4. **生态影响面有限**：`init / add / hash-object / write-tree / log / ls-remote / clone / fetch`（http(s) TLS）均正常；
   需要版本管理的工作流可改用远程链路或不落盘的只读/索引级操作。`git commit` 是**唯一致 crash 路径**。
5. **上游修复依赖**：根因在 aosp-git-cli 的 git 2.56.0 构建（link 失败缺回退 rename 的空指针保护），需上游出修复构建后
   经 `cli.lock.json` 升版（建议并入二期 Maven Central 切换一并处理）；按现工程纪律「不 fork/不改上游」，本期不自行补丁。

## 四、证据与复现依据

### 4.1 既有归档（2026-11-05，模拟器真域）
- `pi-desktop-android/specs/112-cli-integration/logs/2026-11-05/git-commit-segfault/`
  - `avc-link-denied.txt`：logcat SELinux AVC 原文（untrusted_app_34 audit 1008/1009；runas_app 1018+ 多组）。
  - `tombstone-git.txt`：`libc` Fatal signal 11 + DEBUG tombstone（cmdline、backtrace、fault addr 0x0）。
  - `cli-facts-app-untrusted.json`：探针 revision 28 完整结构化结果（gitSmoke 七步 + summary）。

### 4.2 本轮新证（2026-11-07，真机原生 arm64）
- 设备 8f155833（Xiaomi Mi 11 / M2105K81C，Android 11 / API30，`arm64-v8a`）：
  `[cli-probe] git 工作流冒烟 FAIL（commit=SEGFAULT(139)，log=fail，272ms，7 步）`；
  CLI 其余能力 10/10 正常（git 2.56.0 `--version` 回程、`ls-remote` TLS 正常）。

### 4.3 配置层 workaround 对照（全失败）
| 尝试 | 手段 | commit rc |
|---|---|---|
| baseline | `git commit -m` | 139 |
| 关签名 | `merge.gpgSign=false` + `commit.gpgsign=false` | 139 |
| 关 fsync | `core.fsync=none` | 139 |
| 关 fsmonitor | `core.fsmonitor=false` + `core.useBuiltinFSMonitor=false` | 139 |
| 换临时目录 | 仓库内 `TMPDIR=<repo>/tmp`（仍 app_data_file 标签） | 139 |
| 换 ref 格式 | `git init --ref-format=reftable` | init 自身即 139 |

`link(2)` 被拒是 SELinux **域 + type** 层面强制策略，任何 git 配置都改变不了内核裁决 ⇒ **配置层无解**。
mksh R59 无 `link` 内建（rc=127），无法用 shell 内建绕过。

## 五、产品处置建议（供决策）

1. **文档化规避（当前策略）**：能力清单/提示明示「设备 SELinux 禁 App 数据目录 hardlink，`git commit` 本地落库在当前
   git 构建上会崩溃」；引导需版本管理的工作流走 `git ls-remote` / clone / fetch（TLS 已验），或评估可写且允许 link 的
   外部存储（SAF，后续模块）。
2. **修上游构建（根治）**：向 `aosp-git-cli` 反馈「link 失败应回退 rename（POSIX 语义）」缺陷，拿到修复构建后经
   `cli.lock.json` 升版。**真机原生 arm64 已确认非模拟器翻译层问题**，修复优先级可上调。
3. **不 fork / 不改上游**：遵现工程纪律，本期不自行 patch git 二进制；修复并入后续 Maven 切换轮。
