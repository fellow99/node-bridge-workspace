**发现（产品级）**：PRB-04a/04b 在 20261105 模拟器批次与 20261106 真机批次**完全一致复现**（同错误文本），
属 bridge 打包链路的真实缺陷：`libnode_host_client.so`（`-z undefs`，napi 符号缺省解析）在 process.dlopen 时
无法在 linker 全局可见区找到 `napi_*` 符号。

**根因（ELF 铁证，20261106）**：addon 的 `DT_NEEDED` = `[liblog, libdl, libc]`，**缺 `libnode.so`**——
与 [CMakeLists.txt](/d/node-bridge-workspace/aosp-node-bridge/node-bridge/src/main/cpp/CMakeLists.txt) 设计注释
「libnode_host_client.so 必须留下 DT_NEEDED libnode.so」矛盾；API 26 linker 不会把已 dlopen（RTLD_GLOBAL）
库的符号供给无依赖关系的 addon（Android 15/API 36 的同形态能过系 linker 版本行为差异）。

**修复（20261106-6 批次闭环）**：`tools/build-bridge.mjs` addon 链接加 `-L <libnode 目录> -l:libnode.so -Wl,--no-as-needed`
（libnode.so 从 node-runtime AAR 提取；`--libnode` 可显式指定），产物 `DT_NEEDED = [libnode.so, liblog, libdl, libc]`。
新 addon 14,384 B（修复前 10,968 B）。真机 `-r` 更新安装复测：**6 PASS / 0 FAIL / 0 BLOCKED**（详见
`aosp-node-bridge/logs/20261106-6/DEV_CHECKLIST.md`）。

- 0 FAIL（20261106-5 复测；此前 TC-003-06 FAIL 已修复，见下）

**发现与修复（产品级，git-cli 仓 0f5b1df）**：TC-003-06 `git clone --no-local` 在应用沙箱内
恒定失败（`fatal: cannot exec 'git-upload-pack '<repo>'': No such file or directory`），
模拟器与真机全复现。根因：git 交叉编译默认 `SHELL_PATH=/bin/sh`，而 Android 无 `/bin/sh`
（仅 `/system/bin/sh`）；git_connect 本地协议以 `use_shell=1` spawn `/bin/sh -c 'git-upload-pack …'`
⇒ exec ENOENT。修复（20261106-5 真机验证 **17P/0F/9S**）：
（1）SHELL_PATH 只对引用它的 4 个 TU 注入 C 宏（make 变量 SHELL_PATH 保留宿主可用）；
（2）宏值 `//system/bin/sh`（双斜杠豁免 git-bash MSYS2 参数转换，bionic 等价解析）；
（3）S9 新增 SHELL_PATH 门禁（必含 `//system/bin/sh`、禁含 MSYS2 污染串）；修复后
GIT_TRACE 实锤 `start_command: //system/bin/sh -c 'git-upload-pack …'` → spawn 成功。
