## 2. 实测证据（2026-11-05，模拟器 p0probe 全工具链环境复现）

> 环境：emulator arm64 翻译环境，`org.fellow99.p0probe` 含 node/python/uv/git/pnpm 全部 CLI 与
> 物化工具树。以下每条均为设备实测，方法可复现。

### 2.1 node

| 现象 | 实测结果 | 根因 |
|---|---|---|
| `\p{L}` 不可用 | `node t1.js` → `SyntaxError: Invalid regular expression: /\p{L}/u: Invalid property name` | CLI `--with-intl=none`（D7 有意取舍）；`typeof Intl === 'undefined'` |
| "静默死亡" | `throw new Error('boom')` → exit 1、stdout/stderr **均 0 字节**；错误文案只在 `logcat tag=nodejs`（完整 stack） | **平台事实**：上游 `src/util.cc`/`debug_utils.cc` 的 `__ANDROID__` 分支把未捕获异常写入系统日志而非 stderr；仓库 `specs/003-cli/test-cases.md` TC-003-05 早已记录"stderr 空为平台事实"。**不是 bug，是 CLI 契约缺陷**（exit 码正确） |

**B1 修复验证**：`NODE_OPTIONS=--require=hook.js`（hook 挂 uncaughtException/unhandledRejection →
stderr 写 stack → exit 1）后，运行时未捕获与**主脚本语法错误**均全量到 stderr；`console.log/error`
正常 stdio 径不受影响（未挂 hook 时 `console.error` 到 stderr 亦正常）。

### 2.2 python / uv

| 现象 | 实测结果 | 根因 |
|---|---|---|
| `python -m venv` 必挂 | `Error: Command '[...]/bin/python', '-m', 'ensurepip', ... returned non-zero exit status 1`；`pyvenv.cfg home = …/files/home/bin`（python 软链所在目录，无 stdlib）→ venv 解释器找不到 stdlib | venv 把 `home` 写成**解释器软链所在目录**；不是 `-I` 本身，是"非标准前缀布局 × prefix 假设" |
| venv 修法验证 | 覆写 `home` → 指向含 stdlib 的 prefix 后 `.venv/bin/python -m ensurepip` 成功（pip 26.2.2 装成） | — |
| uv 解释器发现失败 | `uv venv` → `error: Failed to inspect Python interpreter from first executable in the search path at …/bin/python … Could not find platform independent/dependent libraries`；**set PYTHONHOME 无效** | uv 用隔离模式检查解释器，不吃 PYTHONHOME → 解释器不自洽即失败 |
| uv 修法验证 | 构造**自洽 prefix**（`pyvenv.cfg(home=自身) + bin/python→libpython_cli.so + lib/python3.14→stdlib`）后：`$R/bin/python` 无 PYTHONHOME、甚至 `-I` 下 base_prefix 解析正确；`UV_PYTHON=$R/bin/python uv venv` 一次成功 | 根修路径确认 |
| uv venv 的 home 埋雷 | 新建 `.venv/pyvenv.cfg home = /data/app/…==/lib/arm64`（**符号解析后的真实目录**，无 stdlib）→ 刚建好即废 | **uv 自身缺陷**（对软链/共享库解释器写死 realpath home），只能建后覆写或 fork-patch uv |
| `uv python install` | 无 android managed 构建 | 生态：上游无 android 托管 CPython；设计已因 C2（运行期不得下载可执行件）排除 |
| `uv pip install` 二进制轮子 | fastapi→pydantic-core 无 `cpython-3.14-aarch64-linux-android` 轮子；回退源码编译 → rustup 目标 `aarch64-unknown-linux-android` 不受支持；设备无编译器 | 生态级（见 §6） |

### 2.3 软链前提（C1 可行性）

PTY/CLI 层软链**受支持且已在使用**：harness 命令农场 `home/bin/{node,python,git,…}` 软链指向
NLD `.so` 即为生产用例；C1 所需的"python→NLD 软链 exec"、"`lib/python3.14`→filesDir 软链读数据"、
venv 两级软链均实测通过（exec 时 SELinux 只查目标文件标签，NLD 可 exec）。

**分层注意**：agent 进程内 node runtime 给 `fs.symlink` 装了 EACCES 回退垫片
（`shims/fs-symlink.js`，FALLBACK_CODES=EACCES/EPERM/ENOTSUP/EOPNOTSUPP）——那是受限沙箱上下文，
与 PTY/CLI 层不同域。C1 据此保留对 stdlib 软链的 **copy 兜底**（软链失败 → 整树复制，幂等），
求确定性。

## 3. 决策汇总

| # | 决策点 | 结论 |
|---|---|---|
| ① | node ICU | **full-icu + 内嵌**（CLI 58.4 MiB → 预估 100–106 MiB；ICU 代码 ≈12–15MiB + 全量数据 ≈24–30MiB；首产后 lock 实测回填） |
| ② | node 错误可见性 | **B1**：环境层 `NODE_OPTIONS=--require=hook.js`（原生崩溃不可见 = 已接受残余边界） |
| ③ | python/uv prefix | **C1**：环境层自洽 prefix + 软链 + stdlib 软链 copy 兜底；uv venv 建后 `home` 覆写；终端手敲 `python -m venv` 亦自愈 |
| ④ | pnpm registry | 并入同一 bootstrap：`pnpm config set registry <DSH_ANDROID_REGISTRY>` |
| ⑤ | uv 二进制轮子边界 | **E1** 能力边界披露；E2-lite（自建白名单 android 轮子）记触发条件 |

## 4. 分仓落地

### 4.1 aosp-node-cli（本工作区实现）

- configure：`--with-intl=none` → **`--with-intl=full-icu`**（内嵌数据；无 `NODE_ICU_DATA` 依赖）。
  小 ICU 走树内 `deps/icu-small` 无需网络；full 需完整 icu4c 数据源 →
- 新增 **fetch-icu** 步骤（钉版本 + sha256 校验，`--with-icu-source` 喂 configure；参照
  aosp-python-cli vendored openssl/sqlite 模式）；lock 新增 `sources.icu` 记录。
- 校验/体积：`provision --inspect` 发布形态全套门禁不变；size/sha 重测回填 lock（预估
  100–106 MiB 以首产为准）。体积缓解沿既有规划（Play 动态特性模块）登记，不阻塞。
- 文档：D7"有意分歧"事实记录更正为 full-icu（原 intl=none 口径作废）；顺手修
  `specs/STRUCTURE.md` 注明过的 `build-node-cli-android.sh:10` 注释事实错误。
- 验证用例（CI + 真机 arm64）：`/\p{ID_Start}/u.test('a')===true`；`new Intl.NumberFormat('zh-CN').format(1234)==='1,234'`；**Express 5 起服 + curl 200**。

> 注：`small-icu` 按上游口径已含 `\p{...}` 所需字符属性数据（属性非语言环境数据）；full-icu
> 额外提供全部 Intl locale。选 full = 终端内 node 面向用户的完整 Intl。

### 4.2 dsh-desktop-android 环境引导层（需求交接，非本仓源码实现）

1. **错误 hook（B1）**：随包内置 `error-hook.js`；harness `pty.spawn` / 工具 spawn 统一注入
   `NODE_OPTIONS=--require=<hook>`；hook 捕获 uncaughtException/unhandledRejection →
   stderr（stack）+ `process.exit(1)`；对 `--no-options` 等关闭场景标记降级。
2. **自洽 prefix（C1）**：工作区初始化幂等生成固定位置的 `.pyruntime` 风格自洽 prefix：
   - `pyvenv.cfg`：`home = <prefix 自身>`；
   - `bin/python`（及 python3/python3.x）软链 → `nativeLibraryDir/libpython_cli.so`；
   - `lib/python3.14` 软链 → 物化 stdlib；**软链失败降级为整树复制**（幂等）；
   - `home/bin/lib/python3.14` 软链 → 物化 stdlib，使终端手敲 `python -m venv` 的
     `home`（= 软链所在目录）也能找到 stdlib，达自愈。
   - env 注入：`PYTHONHOME`（保留，兼容直接调用）、`UV_PYTHON=<prefix>/bin/python`、
     `PATH`/`LD_LIBRARY_PATH`/`SSL_CERT_FILE` 既有口径不变。
3. **uv 自愈**：`uv venv`/`uv sync` 建环境后幂等覆写 `pyvenv.cfg home` 指向含 stdlib 的 prefix
   （uv 固有缺陷，见 §2.2）。
4. **registry（④）**：`pnpm config set registry $DSH_ANDROID_REGISTRY`（与 npm 同源镜像），
   bootstrap 注入。

### 4.3 能力边界披露（消费方文档：aosp-node-cli/python-cli/uv-cli README + dsh 能力清单）

- node：未捕获异常/语法错误文案默认走 **logcat(tag=nodejs)**，stderr 为空（CLI 平台事实）；
  经 B1 环境后 JS 级错误可读；**原生致命错误仍不可见** stderr → 依赖 exit 码 + logcat。
- uv：**纯 py wheel 域可用**；含 C/Rust 扩展的包按"是否恰好有 android 轮子"而定（现状≈不可装）；
  **sdist 不可设备编译**；`uv python install` 不支持。
- python：sdist 不可设备编译；venv/uv 依赖 harness 环境引导（现已自愈），裸执行不保证。

## 5. 验证与回归计划（真机 arm64）

1. `node -e` 三连：`\p{ID_Start}` 属性转义、`Intl.NumberFormat('zh-CN')` 全 locale、Express 5 起服。
2. B1：harness 终端里 `node -e "throw new Error('boom')"` → stderr 可见 stack、exit 1；
   主脚本语法错误同验。
3. C1：`rm -rf .venv .pyruntime && sh start.sh` 从零重建（当前 6.6s 基线）→ 服务 200；
   另验 `python -m venv .v && .v/bin/python -m ensurepip` 成功（自愈）；
   `uv venv`（UV_PYTHON 自洽 prefix）→ 建后 home 已修 → `uv pip install <纯 py 包>` 成功。
4. uv 边界：`uv pip install fastapi` → 按 E1 预期失败，文案为"无 android 轮子"，非静默。
5. 回归：git init/add/commit/log、pnpm `install --frozen-lockfile` + registry 镜像、
   npm/pip 冒烟。

## 6. 残余边界与后续触发条件

- **原生致命错误 stderr 不可见**（B1 残余）：如需，后续叠 B3（harness 在 exit≠0 时抓
  logcat nodejs 拼回）。不阻塞本轮。
- **E2-lite 触发条件**：出现"必须可装的二进制轮子依赖"且上游无 android 轮子（例：pydantic-core
  类成为硬需求）→ 立项"构建机 PyO3 abi3 交叉编译白名单 ≤5 包 + 随包私有 index"。
  YAGNI，当前不实施。
- **uv pyvenv.cfg home 缺陷**：持续以环境层覆写自愈；若接受违反"fetch 不改源"纪律，
  可选 fork-patch uv（不推荐，仅登记）。
